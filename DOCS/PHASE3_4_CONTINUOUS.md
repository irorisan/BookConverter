# Phase 3・4 — CUI連続変換と検証

## 期待動作・影響

BAT引数ありはそのまま最初のバッチ、引数なしはパス待機。結果集計後は同じPowerShellプロセスで待機へ戻る。「まるまる漫画」→「さんかく漫画」→qを受け付け、各回の作品名・巻数検出・入力一覧・進捗・並列キュー・結果・一時領域を初期化する。変換本体は1バッチ関数として共用し、品質探索・60MiB/70MiB・命名・ページ順は維持する。

入力は絶対パス。単一パスは空白入りでもよく、複数は空白区切りで各空白入りパスをダブルクォートで囲む。引用符内のセミコロン・$等も文字列として扱う。コード評価はしない。空行・不正引用符・存在しないパス・未対応形式は待機に復帰。一部の巻の失敗は集計後に復帰し、後片付け失敗は安全のため異常終了。待機中のq/exitとEOFで正常終了。変換中の追加投入は対象外。

## 自動テストと受け入れ条件

- PowerShell 7.6（Windows / .NET 10）で全PS1をパース、PS1のUTF-8（BOM任意）を検証。
- パスの字句分割：日本語・空白・引用符・複数・末尾バックスラッシュ・評価文字・不正入力。
- 実BATを引数あり/なしで起動し、同じCUIで異なる2作品を連続処理。1巻/複数巻、作品名再入力、進捗分母・結果のリセットを検証。
- 空行・不存在・未対応・失敗巻→正常巻・同名スキップ・q/exit・EOFを検証。入力と既存出力をSHA-256照合し、一時ファイル残留を検査。
- CIは小型CBZ経路とEPUB/フォルダ等の外部ツール不要の経路を検証する。WinRAR・avifenc・dwebpを使用するE2Eは未検証。CI結果はPRの最新HEADで確認する。

## Windows実機の具体的な確認手順（未実施）

1. Windows版、`$PSVersionTable`、WinRAR・avifenc・dwebpのバージョン、CPUを記録。元データのコピーを専用作業フォルダに置き、`Get-FileHash -Algorithm SHA256` で入力と既存出力を記録する。
2. Windows TerminalでBATへ「まるまる漫画」の複数巻をドロップして起動。作品名・並列数を確定。集計後に「さんかく漫画」をコンソールにドロップし、パス挿入を確認してEnter。作品名候補・[1/N]・集計が初期化されることを確認しq。Console Hostでも同じ操作を行う。
3. 両ホストでBATを引数なし起動。「パスのコピー」→貼り付け→Enterで同じ2作品を処理。空行、不存在、txt、同名出力、破損EPUBの後に正常CBZを投入し、exitで終了する。
4. `python tests/baseline/generate_fixtures.py --out tests/baseline/_generated --large` を実行。正確に60MiBのCBZは出力と原本のSHA-256一致。+1バイトはAVIF分岐を確認（合成ダミーのエンコード成功は要求しない）。
5. 合法な60MiB超のJPEG/PNG/WebP素材を用意し、WinRARによるZIP/CBZ/RAR展開、dwebp、avifencを通す。並列1と複数でページ数・自然順・出力名を比較。Q30〜95、最大12ページ×5試算、最大3回、68MiB予測・70MiB目標と超過警告を記録する。
6. Phase 0のEPUB素材でspineの青→赤、表紙追加、危険パス拒否を確認。出力のZIP Store、枚数・名前・サイズを照合する。原本と既存出力のハッシュ不変、一時領域と子プロセスの残留なしを確認する。
7. 日時・ホスト・入力/出力容量・Q・並列・時間・ハッシュ・結果・差異を記録する。Windows Terminal/Console Hostの実ドロップと外部ツールE2Eは、この記録が得られるまで未確認とする。

### ZIP Storeライター導入の履歴（当時はWindows PowerShell 5.1）

quality #30では連続変換スモーク・入力テストは成功したが、追加回帰でEPUB出力のZIPメソッドがStore（0）ではないことを検出した。.NET Frameworkの`ZipArchive` + `NoCompression`はメソッドDeflate（8）となるため、既存資料のStore契約を満たしていなかった。期待値を緩めず、完成CBZの新規書き込みをストリーミングのStoreライターへ置き換える。画像バイト列・順序・名前とCBZ原本コピー経路は変えない。UTF-8ファイル名、CRC32、ZIP64を扱い、書き込みは私有の一時CBZだけで行う。既存の再読み込み検証と上書きしない最終Moveを維持する。

- Windows CI quality [#31](https://github.com/irorisan/BookConverter/actions/runs/39486634257)（実装HEAD `0ffe1d1`）で全自動テスト成功。最終資料・未使用コード整理後も最新HEADで再確認する。
- ZIP64は当時65,535エントリ境界を.NET Frameworkで再読込して確認。7.6移行時も同じC#ライターを.NET 10でコンパイルし、同境界・日本語名・ペイロード・上書き拒否の回帰を実行する。4GiB超の実データ境界は未実測。CRC32/Storeと画像バイト列はPythonのZIP読込でも検証している。
