# BookConverter — PowerShell CUI改修計画

> Status: Planning / 方針更新 2026-10-21  
> 対象: Windows用の漫画・画像主体EPUBからCBZ/AVIFへ変換する既存ツール  
> 正本: 本書と [既存挙動の基準・テスト資料](./PHASE0_BASELINE.md)  
> 開発規約: [AGENTS.md](../AGENTS.md)

## 1. 現在の決定事項

**BookConverterは現行PowerShell + BATの変換処理を維持し、CUIの操作性・進捗・結果表示を最小限の変更で改善する。**

- **採用技術**: Windows PowerShellを主処理とし、既存のBATによるドラッグ＆ドロップ起動を継続する。AVIF変換は既存の `avifenc`、必要なWebPデコードは `dwebp`、非EPUBアーカイブの展開は当面既存のWinRAR利用を前提とする。
- **非採用**: Rust/Tauri/React/TypeScript/Tailwindへの移植、WebViewを使うGUI、凝ったダッシュボード、アプリの全面リライト、EXE化は**現計画から外す**。技術変更は実測された必要性が出たときに改めて検討する。
- **UI方針**: 画面は**CUI（テキスト主体のコンソール）**。追加する視覚表現は全体/現在巻の進捗バー、状態、処理ログ、終了サマリー程度に限定。外部UIフレームワークを導入しない。
- **実装方針**: 現在動いている変換ロジックとユーザー操作を土台に、見せ方だけを段階的に整理する。実測でボトルネックが確認されない限り、画像圧縮アルゴリズム・並列方式・品質探索は変更しない。
- **開発規約**: Docs First → TDD（Red）→ 最小実装（Green/Refactor）→ 不要物と資料整合の確認。不要な旧API互換やデータ移行は設けない。ただし原本と既存出力の保護は絶対条件。

### 更新理由と影響

以前の計画はデスクトップ向けの高度なGUIを前提としていた。しかしユーザーが求めるのは**今のCUIの操作方法を変えず、現在の処理・進捗が一目でわかること**。画面を作り直すためだけの言語・アプリ基盤移植をしない方がKISSで、リスクも工数も小さい。

**旧PowerShell版と別の新アプリを作る計画は破棄**。Phase 0で作成した合成CBZ/EPUBテスト素材・動作仕様の記録は引き続き利用する。テスト用Pythonスクリプトは開発補助として残し、**変換ツールの実行時依存にはしない**。

## 2. 現行機能の維持範囲（改修で変更しない）

| 分野 | 維持する仕様 |
|---|---|
| 入力 | ZIP / CBZ / RAR / EPUB / 画像フォルダ、複数の巻をBATへドラッグ＆ドロップ |
| 入力検出 | 巻・単巻・コンテナフォルダの判定、既存の探索範囲、完成出力の再投入回避 |
| 命名 | 同一シリーズ名を一括指定、巻数の検出、`v01` 形式、末尾 `b/B` の正規化、単巻/雑誌は元名ベース |
| 出力 | 入力元の親ディレクトリに `avif変換cbz/` を作成し、CBZを出力 |
| サイズ判定 | 60MiB以下は画像再圧縮なし（CBZは原本をバイトコピー）。60MiB超はAVIF変換対象 |
| 品質探索 | Q30〜95、最大12ページの代表抽出×最大5回の品質試算、内部目標68MiB、全体最大3試行 |
| 上限 | 完成CBZは70MiB以内を**目指す**。達成できない場合は最小候補を警告付きで保存し、成功と区別 |
| 並列 | 既存の自動並列数（論理CPUの半分、最大8）、手動1〜16、`avifenc -s 6 -j 1` |
| 画像 | JPEG/PNG/WebPを変換対象とし、GIF/BMP/AVIFは原形保持。WebPは必要時に `dwebp` を利用 |
| EPUB | 画像主体を対象にOPF/spineの読書順、表紙を重複させない処理、異常入力の拒否 |
| 順序・検証 | ページの自然順（EPUBはspine順）、CBZ Store、件数/名前/サイズの確認 |
| 安全性 | 元ファイルは削除・上書きしない。同名出力はスキップ。失敗時の部分出力・一時ファイルを適切に処理 |

個別の境界条件・テスト入力は [PHASE0_BASELINE.md](./PHASE0_BASELINE.md) を参照。上記は旧版コードから得た仕様であり、**Windows実機のすべてのケースで実測確認されたわけではない**。

## 3. CUI改修の要求（MVP）

### 基本操作フロー

1. ユーザーが従来どおりファイル・フォルダをBATにドラッグ＆ドロップする。
2. 既存の入力判定と作品名の入力を実行する。シリーズ名は一括入力（巻数なしは元名使用）。既存の並列数選択を維持する。
3. 画面に**処理対象・対象巻数・出力先・並列数**を見やすく表示する。ファイルごとに衝突・スキップする場合は理由を示す。
4. 変換中は「何巻目/全巻」「現在の巻名」「現在工程（解析・品質探索・AVIF変換・CBZ作成・検証）」「ページ数・完了数」を表示する。
5. 終了後は成功、スキップ、70MiB超過警告、失敗を分けて集計し、処理結果と出力先を示す。

### 推奨表示例（装飾仕様ではなく情報設計）

```text
BookConverter
対象: 12巻 / 作品名: ONE PIECE / 並列: 自動(8)
出力: ...\avif変換cbz\

[07/12] ONE PIECE v50.cbz
入力: 186.4 MiB  |  処理: 品質探索 → エンコード Q70
ページ: 148 / 200   [###############-----] 74%

[OK]    ONE PIECE v49.cbz  65.2 MiB
[WARN]  ONE PIECE v48.cbz  70MiBを超過
[SKIP]  ONE PIECE v47.cbz  同名出力が存在
[ERROR] ONE PIECE v46.cbz  詳細はエラーログを確認

終了: 成功 8 / 上限超過 1 / スキップ 2 / 失敗 1
```

※数値・タイトル・状態はすべて**表示サンプル**。実データの測定結果ではない。

### CUI実装のルール

- 可能ならPowerShell標準の `Write-Progress`、簡潔な `Write-Host` / `Write-Output` を利用する。ANSI制御や依存ライブラリ、複雑な全画面再描画は必須にしない。
- **全体の巻進捗**と**現在の巻のページ/工程進捗**を区別する。単一画面の複雑なレイアウトや疑似ウィンドウを作らない。
- 並列処理中の表示・ログ更新を一元化して、出力が互いに混ざらないようにする。完了したページ数と工程は**実際の処理結果**に基づいて更新する。
- 工程によってページ総数がまだ分からない場合は不明と表示する。根拠のないETAや進捗率を表示しない。品質探索中の試行も巻全体のページ完了として数えない。
- ログは詳細すぎない粒度にし、エラーは理由と入力名を表示する。必要なら詳細ログを別途残す。日本語パス・長い名前・非対話的な実行時の表示崩れにも配慮する。
- Ctrl+Cや例外処理は既存の安全性を壊さないこと。中断時の子プロセスと作業フォルダの取り扱いは実装前に現状を確認し、必要な修正はテストを用意して別途行う。
- ドラッグ＆ドロップ時の入力、シリーズ名の一度だけの指定、出力パスの仕様を勝手に変更しない。

## 4. コード構成の基本方針

```text
BookConverter (Windows)
  Convert-Manga.bat                 # 既存形式のドラッグ＆ドロップ起動
       |
       v
  Convert-Manga.ps1                 # 既存のファイル検出・命名・変換処理
       |-- 状態報告 / 進捗表示      # PowerShell標準機能中心、必要分のみ整理
       |-- EPUB処理                 # 既存スクリプトの役割を維持
       |-- WinRAR / dwebp / avifenc # 既存の外部ツール呼び出し
       +-- avif変換cbz/            # 完成品、原本は不変更
```

この構成は概念図。**現在のGitHubリポジトリに変換本体がチェックイン済みという意味ではない**。既存のスタンドアロンZIPを基準に、実装段階でソースの管理方法を整理する。分割のためだけに複数モジュールへ分けたり、不要なアプリ基盤を導入したりしない。

## 5. 開発順序（旧Rust/Tauri移植ロードマップを置換）

| 段階 | 内容 | 受け入れ条件 |
|---|---|---|
| **P0: 基準の維持** | 既存の合成CBZ/EPUBテストと [Phase 0資料](./PHASE0_BASELINE.md) を参照し、変換本体・外部ツールの所在とWindows実機の現状を記録 | 現行版の動作と未検証点が明確 |
| **P1: CUI表示の設計とテスト** | 工程と進捗イベントの定義、表示例と受け入れ条件、入力/出力保護の回帰テストを追加 | 仕様書が先に更新され、改善予定のテストがRedを示す |
| **P2: 最小改修** | PowerShellの既存処理に進捗報告と終了サマリーを接続。必要なログ整理だけ実施 | 従来の変換結果を変えず、巻/ページ/工程が分かる |
| **P3: 検証・整理** | 不要コードと説明の矛盾を除去、WindowsでBAT操作・変換・中断/異常系を検証、CIを改善 | テスト成功、原本保護、最新HEADの`quality`成功 |
| **将来必要になった場合のみ** | AVIF速度、RAR依存の整理、配布方法の変更等を実測して再検討 | ベンチマークと具体的な問題に基づき別PRで決める |

**従来の「Phase 1: Tauri雛形 → Rust移植 → GUI仕上げ → EXE化」は現在の開発予定に含めない。** GUI試作品はUI案の参考資料であり、移植の必要条件ではない。

## 6. テスト・CI

- 開発サイクルは [AGENTS.md](../AGENTS.md) のDocs First/TDD/KISSに従う。ドキュメントだけの変更では、不要な製品機能テスト追加は求めない。
- **回帰対象**: ファイル検出、巻数命名、同名スキップ、60MiB閾値、Qの試算、EPUBの表紙/spine順、自然順、出力ファイル保護。
- **新規対象**: 1巻/複数巻、スキップ・70MiB超過・失敗、進捗の非減少、並列ログ混線、ページ数未知、最後の終了サマリー、Ctrl+C中断後の原本保護。
- 既存のPython `tests/baseline` は**合成入力の構造検証**であり、PowerShellエンジンそのもののテストではない。
- `quality` は現状ドキュメント形式/リンクと合成フィクスチャテストのみ。PowerShell本体がリポジトリに追加されたら、Windows runnerでスクリプトのパースチェック、PowerShellの単体テスト（例: Pester）、可能な変換スモークテストを追加する。必要性を確認してからPSScriptAnalyzer等の導入を判断する。
- 完了報告は**最新コミットの必要な `quality` 成功後のみ**。CIの対象外だった内容は未検証と明記する。マージはユーザーから明示依頼があった場合のみ。

## 7. リスクと非目標

- **実行環境**: Windows PowerShell・BAT、外部 `avifenc`/`dwebp`/WinRAR の導入・配布状態を確認する。利用条件やDLL等は無検証で同梱しない。
- **変換安全性**: ZIP/EPUBの危険な参照パス、破損ファイル、同名出力の競合、例外・中断時の未完成ファイルに注意する。対策が不足していれば別PRでテストを先行させる。
- **表示上の正確性**: AVIFのサンプル品質探索と本変換を混同せず、実際に測れていない項目を進捗に利用しない。
- **非目標**: Tauri/Rust移植、WebベースGUI、ライブラリ/表紙一覧、インストーラー、無条件の単一EXE化、OCR、作品メタデータ自動取得、クラウド/Kavita連携。既存のCBZ変換に不要な機能を増やさない。
- **性能**: 言語変更だけでは`avifenc`の計算速度を改善できない。速度は必要があれば計測し、既存変換パラメータを変更する前に画質・容量・時間の比較を行う。

## 8. Definition of Done

- [ ] ZIP/CBZ/RAR/EPUB/画像フォルダを従来どおりBATに投入でき、作品名を一括指定できる。
- [ ] 全体・巻・工程・ページの進捗と成功/スキップ/超過/失敗の結果が読み取れる。
- [ ] 命名、ページ順、変換結果、60MiB/70MiBの仕様が意図せず変更されない。
- [ ] 元ファイルや同名の既存出力は上書き・削除されない。
- [ ] 追加テスト/回帰テスト、Windows実機スモークが必要な範囲で成功する。
- [ ] ドキュメントとスクリプト・CIの内容が整合し、最新HEADの `quality` 成功を確認する。
