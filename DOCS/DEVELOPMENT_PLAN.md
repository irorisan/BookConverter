# BookConverter — PowerShell CUI改修計画

> Status: Phase 3・4実装／検証 / 方針更新 2026-10-21  
> 対象: Windows用の漫画・画像主体EPUBからCBZ/AVIFへ変換する既存ツール  
> 正本: 本書と [既存挙動の基準・テスト資料](./PHASE0_BASELINE.md)  
> 開発規約: [AGENTS.md](../AGENTS.md)

## 1. 現在の決定事項

**BookConverterは現行PowerShell + BATの変換処理を維持し、CUIの操作性・進捗・結果表示を最小限の変更で改善する。**

- **2026-10-22 現行入口（最優先）**: 変換の入口は`Convert-Manga.bat`（漫画）と`Convert-Manga-Magazine.bat`（雑誌）の2種類のみ。**両方Hybrid固定**でGPU12プロセス＋CPU本変換4プロセス、品質探索はGPU主体＋CPU3ページ校正（既定`CpuProbeWorkers=0`）。Windows Terminal上のPowerShell 7.6起動を維持。旧CPU単独・GPU単独・Legacy変換モード、旧並列入力の実装、3つの旧変換BATは撤去する。GPU用FFmpeg・CPU用avifenc・WebPデコードの各機能はHybridに必須なので保持。
- **既存の歴史的なベンチマーク/Phase 0記録**は資料として残すが、本文で「CPU版/旧GPU版」などに言及している過去の仕様は現在の実装には適用しない。現在の仕様はこの節と`HYBRID_AVIF.md`を優先する。
- **採用技術**: PowerShell 7.6（Windows）を主処理とし、既存のBATによるドラッグ＆ドロップ起動を継続する。
- **Windows Terminalで起動**: 漫画・雑誌のHybrid変換BAT 2種類はExplorerのドラッグ＆ドロップをそのまま受付け、短命なBAT/Powershellランチャー経由で `wt.exe -w new new-tab` を使って**新規Windows Terminalウィンドウ**内にPowerShell 7.6の変換処理を開始する。CMDウィンドウは起動用のみで変換UIには使わない。Windows Terminalの既定プロファイルには依存せず、`pwsh.exe`を明示実行する。変換完了後は従来どおり同じPowerShellで次の入力待ち。
- **入力保持/安全性**: 漫画/雑誌の入口をBATごとに保持し、複数ドラッグパス・日本語・空白・アンパサンド・セミコロン・シングルクォート・PowerShell特殊文字を**文字列引数**として保持する。Windows Terminalへ渡すコマンドはUTF-16LEの`-EncodedCommand`にして、外部のファイル名やURLを`wt.exe`コマンドとして解釈させない。開始後に同じデータをコピー/移動しない。
- **依存/エラー**: `wt.exe`（Windows Terminalのアプリ実行エイリアス）とPowerShell 7.6を起動前に確認し、どちらかがなければ説明を表示して中止する。Windows Terminalがない場合にCMDへ黙って切り替えない。ExplorerがBATを起動する際にはWindowsの仕様上、短時間CMDウィンドウが開く可能性がある。Updater BATは既存のままで、変換BAT以外を変更しない。
- **検証**: 発行する`wt`引数・PowerShellコードを副作用なしのヘルパーで生成してPowerShell 7.6 Windows CIで検証。2つのBATのモード分離、複数引数・各種危険文字・プロセス引数エスケープ・UTF-16エンコード/復元、起動後の例外・環境依存エラー案内、既存CBZ/EPUBテストを実行する。GUIを伴う実際のExplorerドロップ/Terminal新窓表示はWindows実機で目視確認する。
AVIF変換は既存の `avifenc`、必要なWebPデコードは `dwebp`、非EPUBアーカイブの展開は当面既存のWinRAR利用を前提とする。
- **非採用**: Rust/Tauri/React/TypeScript/Tailwindへの移植、WebViewを使うGUI、凝ったダッシュボード、アプリの全面リライト、EXE化は**現計画から外す**。技術変更は実測された必要性が出たときに改めて検討する。
- **UI方針**: 画面は**CUI（テキスト主体のコンソール）**。追加する視覚表現は全体/現在巻の進捗バー、状態、処理ログ、終了サマリー程度に限定。外部UIフレームワークを導入しない。
- **連続処理**: 1バッチの変換完了後もウィンドウを閉じず、**同じコンソールで別の漫画を受け取り、新バッチとして最初から実行**できるようにする。前バッチのシリーズ名・入力一覧・カウンター・失敗状態を次バッチに引き継がない。
- **実装方針**: 現在動いている変換ロジックとユーザー操作を土台に、見せ方だけを段階的に整理する。実測でボトルネックが確認されない限り、画像圧縮アルゴリズム・並列方式・品質探索は変更しない。
- **入口ごとの命名**: 漫画と雑誌をファイル名の巻数有無で自動分類しない。`Convert-Manga.bat`は漫画用でシリーズ名を一度聞き、番号なしも漫画として別名保存。`Convert-Manga-Magazine.bat`は雑誌・単巻用で入力元の名前を維持。詳細な命名とテスト条件は[入口分離仕様](./MODE_SEPARATION.md)。
- **開発規約**: Docs First → TDD（Red）→ 最小実装（Green/Refactor）→ 不要物と資料整合の確認。不要な旧API互換やデータ移行は設けない。ただし原本と既存出力の保護は絶対条件。

### 更新理由と影響

以前の計画はデスクトップ向けの高度なGUIを前提としていた。しかしユーザーが求めるのは**今のCUIの操作方法を変えず、現在の処理・進捗が一目でわかること**。画面を作り直すためだけの言語・アプリ基盤移植をしない方がKISSで、リスクも工数も小さい。

**旧PowerShell版と別の新アプリを作る計画は破棄**。Phase 0で作成した合成CBZ/EPUBテスト素材・動作仕様の記録は引き続き利用する。テスト用Pythonスクリプトは開発補助として残し、**変換ツールの実行時依存にはしない**。

## 3. CUI改修の要求（MVP）

### 基本操作フロー

1. ユーザーが従来どおりファイル・フォルダをBATにドラッグ＆ドロップする。
2. 入力元の漫画/雑誌は**起動したBATで明示的に指定**する。漫画BATは巻数の有無にかかわらず作品名を1回入力（巻数不明は元ベース名を保持する識別付き命名）。雑誌BATは作品名を変更せず、入力元名を維持する。HybridのGPU12・CPU4プロセスを固定し、旧CPUの並列数質問はしない。
3. 画面に**処理対象・対象巻数・出力先・実際の並列構成**を見やすく表示する。ファイルごとに衝突・スキップする場合は理由を示す。
4. 変換中は「何巻目/全巻」「現在の巻名」「現在工程（解析・品質探索・AVIF変換・CBZ作成・検証）」「ページ数・完了数」を表示する。
5. 終了後は成功、スキップ、70MiB超過警告、失敗を分けて集計し、処理結果と出力先を示す。
6. **コンソールを開いたまま次の入力を待ち**、新しい漫画ファイル/フォルダを受け取ったら、入力検出・シリーズ名入力から新しいバッチを開始する。終了操作があるまで繰り返す。

### GPUプリセットと変換後の工程別所要時間

- NVIDIA GPUモードのFFmpeg `av1_nvenc` は **`-preset p7` 固定**。`-tune hq`、CQ変換、4:2:0、GPU最大12並列、Hybrid内のCPUフォールバック用avifenc設定は維持する。
- **各巻の処理終了後**（成功・容量超過警告・失敗・60MiB以下のCBZコピーを含む）、工程別時間と巻合計を `HH:MM:SS.1桁` で表示する。既存出力のスキップは時間内訳の対象外。既存のバッチ全体所要時間は従来どおり残す。
- 工程は「入力準備」「展開・EPUB抽出」「品質探索」「AVIF本変換」「AVIFデコード検証（GPU本変換）」「CBZ書込・コピー」「CBZ検証・保存」とし、未実行工程は非表示。どの計測にも重複する時間を含めない。
- **品質探索**には試算用のAVIFエンコード・デコード検証を含める。本変換の計測とは分離し、再試行を含む全実行分を積算する。GPUの本変換デコード検証は本変換とは別計測。
- 計測範囲外の時間（起動オーバーヘッド、進捗表示、後片付け等）は「その他」にまとめて合計との整合を確保する。入力待ち・シリーズ名・CPU版の並列数入力時間は除外。実計測でありGPUデバイス単体のハードウェア処理時間ではない。
- Windows CIではp7指定・表示フォーマット・各工程の集計・コピー経路をテストし、実GPUによるNVENC速度/画質のE2Eは実機確認とする。

### GPUエンコード：1画像×最大12FFmpegプロセス（採用構成）

- 実測（同じ約250ページの漫画、各1回）：12プロセス×1画像 = **41.7秒**、6×2 = 43.0秒、4×3 = 44.5秒、3×4 = 46.3秒。各1回測定のため差の統計的な有意性は未確定だが、ユーザー判断で**1画像×12プロセス**に固定する。
- GPU版（漫画・雑誌）の品質探索とAVIF本変換は、**FFmpeg 1プロセスにつきAVIF画像1枚だけ**を出力する。最大12プロセス並行実行する。ページが少ない場合は最大数未満となる。**Hybrid起動時は並列数を質問しない**。
- ベンチマークの1〜4選択、可変バッチサイズ、4画像一括出力の専用処理・テストおよび古いドキュメントは撤去し、使用するエンコード実装を1つに統一する。品質探索の最大12サンプル×最大5試算、試算結果の再利用、68MiB内部目標・70MiB完成目標、再試行、画像順、入力・既存出力の非破壊は変更しない。
- **全ページのFFmpegデコード検証は8画像単位・最大2プロセス**のまま固定（追加のlibavif検証も維持）。NVENCの `-preset p7`、`-tune hq`、CQ変換、`yuv420p` は変更しない。品質探索のデコード検証も従来どおり行う。
- GPUの1プロセス=1出力・最大12並列・失敗時の巻全体失敗と後片付けを製品仕様として維持。Windows CIでは引数・設定用プロンプト無し・GPU BAT小CBZの非破壊パススルー・CPU版の並列選択を検査する。模擬EXEでの9/12ページ変換・失敗テストは7.6移行で削除した。RTX 5070 Tiの実AVIF E2EはCIの対象外。

### AVIFデコード検証のバッチ化（計測値に基づく改善）

以下の全ページ検証はLegacy GPUの契約。実験GPU/HybridはPR #21の最終サンプル方式を使用し、品質探索中のデコードを行わない。[Hybrid仕様](./HYBRID_AVIF.md) を参照。7.6のテスト範囲は [移行仕様](./POWERSHELL_7_6.md) を正本とする。

- 実測: 約250ページ、入力約150MB→出力約70MB、総36.1秒のうちデコード検証8.5秒。GPU版は全ページのFFmpeg検証を引き続き必須とし、**処理回数を減らしても検証対象は減らさない**。
- FFmpegを**8ページ単位（最後は端数）で一括起動**する。各AVIFを独立した入力 `-i` として指定し、`-map 0:v:0 -map 1:v:0 ...` を使ってすべての動画ストリームをデコードする。映像を`-c copy`して検証をすり抜けない。
- `-xerror` と `-max_error_rate 0` でデコード異常を非ゼロ終了にし、どのグループが失敗したか明示する。**グループの失敗を成功扱いしない**。異なる解像度の画像も独立入力・独立ストリームとして扱う。
- 同時に起動する検証FFmpegは最大2プロセス（指定ワーカーが1なら1）。1巻250ページならFFmpeg起動回数は概ね250回→32回に削減する。メモリ消費を抑えるため初回は設定固定とし、実測後に見直す。
- 従来の`tools\\avifdec.exe`があれば全ページの追加デコード検証を継続。失敗時は出力を成功扱いせず一時データを破棄。CPUエンコーダー・p7・品質探索・上限70MiB・原本保持は変更しない。
- Windows CIでは8入力の全`-i`/`-map`引数とPowerShell 7.6構文を検査する。実プロセスの17/250ページ分割・バッチ失敗伝播は模擬EXE依存のため7.6移行で削除した。NVIDIA実機で8.5秒から短縮したかは別途比較し、**速度改善値を保証しない**。

### 変換完了後の連続処理（新規MVP要件）

**目的**: 「まるまる漫画」を全巻変換 → 完了表示 → **同じCUIへ「さんかく漫画」を投入** → 新しいバッチとして変換、を何度でも繰り返せるようにする。

- **起動時**: 従来どおりBATにドラッグ＆ドロップされた引数があれば、その入力で最初のバッチを実行。BATをダブルクリックして**引数なしで起動**しても、入力待ちプロンプトを出す。
- **バッチ終了時**: 成功・失敗・スキップ・警告の内訳を表示した後、コンソールを終了せず**次の漫画入力を待機**する。入力待機中だけ新しいバッチを受け付け、変換中の追加入力やジョブの割り込みは初期スコープ外とする。
- **再投入**: コンソールがパスのドラッグ＆ドロップ挿入に対応している場合、ファイル/フォルダを**既に開いているコンソールの入力行へドロップし、Enterで確定**する。対応しないホストでは**「パスのコピー」→貼り付け→Enter**またはパスを手入力する。標準CUIで「ドロップだけで自動開始」は保証しない。
- **入力形式**: 1つの絶対パス、引用符で囲った空白・日本語を含むパス、複数の引用付きパス（同時ドロップ）を扱う。既存のZIP/CBZ/RAR/EPUB/フォルダ対応と複数巻検出を再利用する。**パス文字列をPowerShellコードとして評価しない**（`Invoke-Expression`等は禁止）。
- **パス検証**: 引用符の扱いを統一し、入力されたパスの存在・形式を検証する。不正/空の入力でCUIが落ちないよう理由を表示し、そのまま再入力を待つ。PowerShellの`Read-Host`は入力長に制約があるため、長いパス列や多数ファイルは**親フォルダを1つ投入**する操作を案内する。<https://learn.microsoft.com/ja-jp/powershell/module/microsoft.powershell.utility/read-host>
- **状態の初期化**: 新バッチごとに対象ファイル一覧、シリーズ名、巻/ページ進捗、容量・品質探索結果、ログ集計、エラー状態、並列実行キュー、一時作業領域を初期化する。**前回のシリーズ名は自動流用しない**。入力毎の既存出力スキップ・原本保護は変えない。
- **異常終了の扱い**: ある漫画の処理が一部失敗しても、そのバッチの終了処理・後片付け・集計を行ってから次入力を受け付ける。予期しない例外でも安全に復帰可能な場合のみ待機に戻り、復帰不能なら詳細を表示して終了する。作業途中の状態のまま再実行しない。
- **終了操作**: 入力待機中に`q`または`exit`を入力してEnterで正常終了。必要があればユーザーはウィンドウを閉じることもできるが、途中変換中は安全なキャンセル処理を優先する。
- **実行ホスト検証**: Windows TerminalとWindows Console Hostで**コンソールへのドラッグ＆ドロップでパスが挿入できるか実機確認**する。パス挿入を保証できないホストでも、手入力/貼り付けで一連のループを利用できる設計にする。ホストによりドロップ場所・動作が異なる可能性がある。
- **KISS**: 変換本体を複製せず、`Process-Batch(inputs)`のような共通処理を「BAT起動時引数」と「次回コンソール入力」の双方から呼び出す。実装上の入口名は仮称で、最小の分割に留める。

#### 連続処理の必須テストケース

| ケース | 期待値 |
|---|---|
| 初回BATへ「まるまる漫画」をドロップ → 完了 → CUIに「さんかく漫画」を入力 | **同じウィンドウ**で2回目のバッチが開始し、出力名は「さんかく漫画」。前作品の巻数・シリーズ名・件数を流用しない |
| BATを引数なしで起動 → フォルダ投入 | 初回から入力待機でき、そのまま変換を開始 |
| 1回目が一部失敗・スキップ → 次の正常な漫画 | 1回目を集計・後片付けしたうえで2回目が正常に開始。失敗件数は持ち越さない |
| 日本語、空白、引用符付きパス、複数ファイルのドロップ | 文字列を安全にパスとして解釈し既存形式の入力を認識 |
| 存在しないパス、空行、未対応形式 | 理由を出して待機に復帰し、ウィンドウを閉じない |
| 入力待機中に`q`/ `exit` | 正常終了。未完成の変換ファイルを新たに生成しない |
| Windows Terminal / Console Host | ドロップは実機で可否と挙動を記録。使えない場合も貼り付けで実行可能 |

### CUI実装のルール

- PowerShell 7.6での既定`Minimal`表示は階層化した進捗の見え方が変わるため、コンソール起動時に `$PSStyle.Progress.View = 'Classic'` を明示し、標準`Write-Progress`で統一する。進捗表示に独自のANSI制御やカーソル移動は使わない。
- **起動ロゴ**: コンソールへのプロセス起動直後に限り、青〜シアンのブロック文字によるオリジナル`BOOK / CONVERTER`バナーを一度だけ表示する。漫画／雑誌のHybrid入口で共通とし、同一プロセス内の次バッチ投入では繰り返さない。静的バナー以外の描画は既存の`Write-Progress`で処理する。
- **ロゴ表示互換性**: Windows Terminal／Console Hostで、出力がコンソール・ANSI有効・横幅60文字以上の場合にだけ青系ANSIカラー版を描画。狭い横幅、ANSI無効、`NO_COLOR`指定、出力リダイレクト時はESCやブロック文字を出さず、短いASCII文字だけの2行に切り替える。どちらも最大表示幅を超えず、画面のクリア・カーソル移動・外部フォントやライブラリに依存しない。
- **ロゴ検証**: バナー生成は副作用なしの関数として切り離し、プレーン／カラー／60字境界／リダイレクト／起動1回をPowerShell 7.6のWindows CIで検証。実ターミナル上の配色やフォントの見栄えは実機目視で確認する。
- **Hybrid品質探索の入力**: CPU品質探索の並列数をBAT起動時に質問しない。既定`-CpuProbeWorkers 0`（GPU主体＋少数CPU校正）を使用し、実験的な1〜8並列への切替はCLI引数で明示する。CPU本変換4並列は変更しない。
- **端末表示**: BATをCMDウィンドウで起動した場合のClassic進捗の見た目は端末の描画仕様に依存する。今回はANSI描画・進捗バーの形状や配色変更は行わない。Windows Terminalでの表示確認は実機で行う。
- **全体のタスク進捗**はID 1で処理済み巻数/総巻数、**現在のタスク進捗**はID 2／親ID 1で品質探索（最大5試行、同時GPU/CPUは最大5+5）・CPU校正（最大3試行）・AVIF本変換（実完了ページ数）の進行を表示。試行・ページは**完了したものだけ**を数え、早期終了では架空の進捗を加算せず完了状態へ遷移する。Classicの標準Write-Progressを使用し、子バーは成功/例外/次工程で閉じる。
- **追加する進捗メトリクス（色・ゲージ形状変更なし）**: 上段は「完了した巻数/総巻数・整数%・バッチ経過時間」、下段は「実際の完了数/予定数・整数%・実測速度・現在工程の経過時間」をStatus文字列に表示。AVIF本変換の速度は完了ページ数/当該パスの経過秒で「枚/s」、品質探索・CPU校正では完了した試行数/経過秒で「試行/s」（ページ/sと混同しない）。初回／0完了／0秒時は速度を「-」とし、推定残り時間は出さない。進捗率は既存の完了数の比率だけを使う。計測開始は各工程の初回表示時、現在の子バー終了時に破棄し、次の工程やバッチへの値の持ち越しを禁止。
- **長い名前・狭幅**: 端末幅が狭い場合は工程名・完了数・%を優先し、速度・経過時間・長い名前は安全に省略できる（実数を捏造しない）。進捗更新は親スレッドのみ。既存のClassic `Write-Progress`とGPU/CPUエンコーダーの進捗更新間隔を維持。新しいグラデーション・状態別の色・アニメーション・テーマ選択UIはこの改修には含めない。
- 各変換パスの開始時は0%から表示し、成功・失敗・キャンセルのいずれでもID 2を完了状態に戻す。全体ID 1はバッチ終了・次の入力待ち前に完了する。非対話端末やCIで表示抑制されても変換処理に影響させない。
- `Write-Host` / `Write-Output` は従来の簡潔なログを維持し、単一画面の複雑なレイアウトや疑似ウィンドウを作らない。
- 並列処理中の表示・ログ更新を一元化して、出力が互いに混ざらないようにする。完了したページ数と工程は**実際の処理結果**に基づいて更新する。
- 工程によってページ総数がまだ分からない場合は不明と表示する。根拠のないETAや進捗率を表示しない。品質探索中の試行も巻全体のページ完了として数えない。
- ログは詳細すぎない粒度にし、エラーは理由と入力名を表示する。必要なら詳細ログを別途残す。日本語パス・長い名前・非対話的な実行時の表示崩れにも配慮する。
- Ctrl+Cや例外処理は既存の安全性を壊さないこと。中断時の子プロセスと作業フォルダの取り扱いは実装前に現状を確認し、必要な修正はテストを用意して別途行う。
- ドラッグ＆ドロップ時の入力、シリーズ名の一度だけの指定、出力パスの仕様を勝手に変更しない。

## 6. テスト・CI

- 開発サイクルは [AGENTS.md](../AGENTS.md) のDocs First/TDD/KISSに従う。ドキュメントだけの変更では、不要な製品機能テスト追加は求めない。
- **回帰対象**: ファイル検出、巻数命名、同名スキップ、60MiB閾値、Qの試算、EPUBの表紙/spine順、自然順、出力ファイル保護。
- **新規対象**: 1巻/複数巻、スキップ・70MiB超過・失敗、進捗の非減少、並列ログ混線、ページ数未知、終了サマリー、Ctrl+C中断後の原本保護。**同じCUIで2バッチ以上連続処理、作品名・カウンターの初期化、空/不正なパスの再入力、複数パス解釈、q/exit終了**も検証。
- 既存のPython `tests/baseline` は**合成入力の構造検証**であり、PowerShellエンジンそのもののテストではない。
- `quality` はWindows runnerで資料・合成フィクスチャ・PowerShell 7.6構文・進捗・小型CBZスモークを検証する。Phase 3・4では入力解釈とBAT経由の連続処理・異常復帰を追加する。必要性を確認してからPSScriptAnalyzer等の導入を判断する。
- 完了報告は**最新コミットの必要な `quality` 成功後のみ**。CIの対象外だった内容は未検証と明記する。マージはユーザーから明示依頼があった場合のみ。

## 7. リスクと非目標

- **実行環境**: PowerShell 7.6（Windows）・BAT、外部 `avifenc`/`dwebp`/WinRAR の導入・配布状態を確認する。利用条件やDLL等は無検証で同梱しない。コンソールへのファイルドロップはOS・ホスト・権限によって異なるため、**貼り付け・手入力を常に代替導線として用意**する。
- **変換安全性**: ZIP/EPUBの危険な参照パス、破損ファイル、同名出力の競合、例外・中断時の未完成ファイルに注意する。対策が不足していれば別PRでテストを先行させる。
- **表示上の正確性**: AVIFのサンプル品質探索と本変換を混同せず、実際に測れていない項目を進捗に利用しない。
- **非目標**: Tauri/Rust移植、WebベースGUI、ライブラリ/表紙一覧、インストーラー、無条件の単一EXE化、OCR、作品メタデータ自動取得、クラウド/Kavita連携。既存のCBZ変換に不要な機能を増やさない。
- **性能**: 言語変更だけでは`avifenc`の計算速度を改善できない。速度は必要があれば計測し、既存変換パラメータを変更する前に画質・容量・時間の比較を行う。
