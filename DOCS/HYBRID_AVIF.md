# GPU＋CPU AVIF実験（2026-10-21）

## 調査・設計

既存入口はCPUとGPU BAT。GPUはFFmpeg av1_nvenc / VBR / p7 / hq /
yuv420p / CQ50..15、品質探索は代表12枚・最大5回、全体再調整は最大3回。
調査開始時のチェックアウトは4出力×3プロセスだったが、最新mainへ追従し、
既存GPUは品質探索・本変換とも1ページ×最大12プロセス固定を基準とする。
CPUはtools/avifenc.exe、ルート、PATHから探索（なければ公式版導入）、
従来設定は -q Q -s 6 -j 1。実行ファイルはリポジトリに含まれない。
ZIP/CBZ/RARはWinRAR、EPUBはOPF/spine、フォルダは自然順。
既存GPU失敗は巻全体を失敗とし、容量超過結果は警告付き保存する。

今回の実験は `-ConversionMode GPU|Hybrid` で明示する。既定Legacyは従来どおり。
実験GPUは1ページ/プロセス最大12、Hybridは同じGPU＋CPU最大4。
親の単一ループが共有FIFOを所有し、完了した枠へ配布するためロック不要。
GPU枠を先に補充し、CPUは残りがGPU枠数以下なら新規取得を止める。
CPU処理を中断・二重実行して追い越さないので、最後のCPU待ちは残り得る。
全ページを事前ステージせず、稼働分だけディスクへコピーする。
GPU失敗（起動失敗・非ゼロ・形式不正）はCPU専用再試行キューへ送る。
CPUは1回再試行し、再失敗は巻を失敗にする。GPUモードでも障害時のみ
CPUを最大1個使用する（通常CPU0）。フォールバックは警告・統計へ明記。
プロセスのタイムアウトとキャンセルファイル、finallyで停止・後片付けを行う。

## 品質・容量

GPUの探索尺度とCPUのlibavif品質は同じ画質ではない。両者を独立に探索し、
それぞれ「全ページをそのエンコーダーで処理した推定」が68MiB以下になる
最大候補を選ぶ。GPU実験の障害時CPU品質は独立指定q95（CPU探索を通常GPU計測へ加算しない）。
Hybridは独立したCPU探索を行う。CPUはAOM AV1 / 8bit / 4:2:0 / speed6 / jobs1を明示。
AVIFというコンテナとAV1というコーデックは共通でも、画質・色・容量の同等性は
保証しない。CPU混在比率は実行時に変動するため、推定は保証ではない。
実容量で既存の3回再調整を適用し、CPU側も自身の品質尺度を5ずつ下げる。
画質低下は品質値と再試行として記録する。70MiB超過は実験モードでは保存しない。
全AVIF（既存AVIF、探索キャッシュも含む）をFFmpegでデコードしてからZIP Store生成。
最終CBZの件数・名前・順序・長さと実容量を検査後にのみ原子的に確定する。
60MiB以下は既存の無変換経路を維持する。

## 計測・受け入れ

巻ごとのJSONに総時間、各工程、各パスのGPU/CPUページ数・試行時間・平均・
スループット・空き枠秒（枠数×経過秒－稼働秒）、ピーク並列数、エラー・再試行を記録。
待機はデバイスのアイドル時間ではなくスケジューラの空き枠時間。
探索と本変換の統計はPhaseで分ける。CPU品質、GPU CQも記録する。
`Benchmark-Hybrid.ps1` は同一入力を独立ディレクトリへコピーして交互に複数回実行し、
入力SHA256・ツール情報・出力容量・品質値を保存し、成功した同条件の中央値を比較する。
画質の同等性は代表ページの目視やデコード後の画質評価で実機確認が必要。
合成モックの所要時間をNVENC性能の証拠にしない。

受け入れテスト: 250ページ、GPU12/CPU4上限・同時稼働・順序・欠損重複、
GPU失敗→CPU、CPU再試行/失敗、タイムアウト、キャンセル・後片付け、
実験モードの容量超過拒否。Windows qualityでPS5.1構文とモックを実行。

実機のGPU対Hybrid中央値、画質同等性、実AVIF/CBZの70MiB境界、WinRAR E2Eは未検証。
約41.7秒の参考値は今回の比較基準にしない。速度改善は未確認、既定への採用なし。

実機測定例（新規の結果ディレクトリを指定、入力は60MiB超）:

ローカル検証: PowerShell 7/Linuxで250ページの実プロセスモック、上限16、
GPUフォールバック・CPU再試行・失敗・キャンセル・タイムアウト・順序を確認。
品質探索＋全変換＋キャッシュ再利用＋ZIP Storeの40ページ検査と84MiB超過拒否を確認。

これらは実AVIFのデコード・画質・GPU速度を検証した結果ではない。
