# GPU＋CPU AVIF実験（2026-10-21）

## 調査・設計

既存入口はCPUとGPU BAT。GPUはFFmpeg av1_nvenc / VBR / p7 / hq /
yuv420p / CQ50..15、品質探索は代表12枚・最大5回、全体再調整は最大3回。
調査開始時のチェックアウトは4出力×3プロセスだったが、最新mainへ追従し、
既存GPUは品質探索・本変換とも1ページ×最大12プロセス固定を基準とする。
CPUはtools/avifenc.exe、ルート、PATHから探索（なければ公式版導入）、
従来設定は -q Q -s 6 -j 1。実行ファイルはリポジトリに含まれない。
ZIP/CBZ/RARはWinRAR、EPUBはOPF/spine、フォルダは自然順。
既存GPU失敗は巻全体を失敗とし、容量超過結果は警告付き保存する。

今回の実験は `-ConversionMode GPU|Hybrid` で明示する。既定Legacyは従来どおり。
実験GPUは1ページ/プロセス最大12、Hybridは同じGPU＋CPU最大4。
親の単一ループが共有FIFOを所有し、完了した枠へ配布するためロック不要。
GPU枠を先に補充し、CPUは残りがGPU枠数以下なら新規取得を止める。
CPU処理を中断・二重実行して追い越さないので、最後のCPU待ちは残り得る。
全ページを事前ステージせず、稼働分だけディスクへコピーする。
GPU失敗（起動失敗・非ゼロ・形式不正）はCPU専用再試行キューへ送る。
CPUは1回再試行し、再失敗は巻を失敗にする。GPUモードでも障害時のみ
CPUを最大1個使用する（通常CPU0）。フォールバックは警告・統計へ明記。
プロセスのタイムアウトとキャンセルファイル、finallyで停止・後片付けを行う。

## 品質・容量

GPUの探索尺度とCPUのlibavif品質は同じ画質ではない。両者を独立に探索し、
それぞれ「全ページをそのエンコーダーで処理した推定」が68MiB以下になる
最大候補を選ぶ。GPU実験の障害時CPU品質は独立指定q95（CPU探索を通常GPU計測へ加算しない）。
Hybridは独立したCPU探索を行う。CPUはAOM AV1 / 8bit / 4:2:0 / speed6 / jobs1を明示。
Hybridは**既定でCPU品質探索0（GPU主体モード）**を使用する。明示的に`-CpuProbeWorkers 1..8`を指定した場合は、GPU（最大12プロセス）とCPU（指定1〜8プロセス）の独立した品質探索をPowerShell 7.6スレッドジョブで**同時開始**する。
CPU探索の並列数は任意のCLI引数`-CpuProbeWorkers 0..8`のみで変更可能。**対話BAT起動・リダイレクト入力・連続バッチのいずれも質問を表示せず、引数なしなら0**。0の場合はGPU品質探索＋CPU最大3枚校正を実行し、CPU本変換の既定4プロセスは維持する。CLIで1〜8を選べる経路は残す。
**新しい`0`（GPU主体モード）**: GPU12枚×最大5回の品質探索だけを行い、CPUの従来12枚×5回の独立品質探索は実行しない。GPUで選択された品質の代表キャッシュから、先頭・中央・末尾の最大3枚を選び、元画像をCPUで短い校正試算（q70→必要ならq50→q40、最大3組）する。CPU AVIFの実サイズが同じ画像のGPUキャッシュサイズ以下になる最初の品質を採用し、すべて超過ならq40を採用し、最終容量が超過した場合のみCPU担当ページをq30まで下げる差分再試行を許容する。GPUとCPUの品質尺度を同一視せず、同じ原画像の実出力サイズを比較する。代表画像が3枚未満なら実枚数だけ試算する。
CPU品質の通常下限をq30からq40に引き上げるが、70MiB制限と出力保護が優先であり、必要なときだけCPU再試行でq30まで下げる。GPU/CPUの品質尺度を同等とはみなさない。
CPU校正はGPU探索の完了後に開始するため、GPU探索中にCPUのエンコード負荷を掛けない。CPU校正で採用した最大3枚のAVIFは**本変換へそのまま再利用**し、GPU探索キャッシュの同じインデックスは差し替える。本変換はGPU12＋CPU4のままで、最初の全ページ処理後に70MiB以内ならCPUページを二度エンコードしない。
**容量超過時だけ**差分再試行する: 前回のGPU/CPU成果物と原本との対応を保持し、まずCPU担当ページだけ元画像から低品質で再変換してGPUページは再利用。まだ超過する場合はGPU担当ページだけ低品質で再変換し、CPUページは再利用する。全ページの無条件再エンコードは禁止。再試行は最大2回（初回＋差分2回）、出力70MiB超過時は保存を拒否する。差分再試行で品質を下げたページと変更前後の品質値はログ・メトリクスに記録する。
`1〜8` は引き続きCPU独立品質探索モード（GPUと並列、最大12枚×5試算）であり、この新しい校正・差分再試行経路は`0`だけに適用する。CPU本変換の`-CpuWorkers`は引き続き独立した4並列（既定）。
CPU**本変換**の並列数 `-CpuWorkers` は従来どおり1〜4（既定4）であり、`CpuProbeWorkers` を変えても本変換のCPU処理枠は変えない。CPU探索の最大8枠だけスケジューラーで許容する。
CPU品質探索0ではCPU校正の最大3代表ページに基づく容量推定となり、12枚×5回のCPU独立探索と画質・出力容量が変わる可能性がある。測定JSONには設定値 `CpuProbeWorkers` を記録する。
各探索の代表12ページ×最大5回・68MiB推定・品質値・品質キャッシュは従来通り独立して保持し、両ジョブの正常終了後に品質値と全パスのメトリクスを収集してから本変換する。
探索用出力はGPU `sample_q*`、CPU `cpu_sample_q*` に分離する。元エントリを共有更新せず、探索用コピーだけを変更する。
どちらかの探索で失敗・キャンセルが起きた場合はもう片方を通知して停止・後片付けし、巻を失敗とする。探索メトリクスはGPU→CPU順で記録する。
GPU単独/Legacyには同時探索を導入しない。
**進捗メトリクス**: 探索・校正中は「完了試行数/上限」「整数%」「完了試行/経過秒（試行/s）」「工程経過時間」。AVIF本変換は「完了ページ数/総ページ数」「整数%」「完了ページ/経過秒（枚/s）」「工程経過時間」。初回の速度は `-`。並列ジョブの値は親側で描画し、進捗率や速度は推測せず実測だけを使用。画面幅が狭いときは補助情報を省略。表示に新しい色・アニメーションは付けない。
**進捗表示**: PowerShell 7.6のClassic表示で、ID1「全体のタスク進捗」は処理済み巻数/総巻数、ID2「現在のタスク進捗」は現在の探索／CPU校正／本変換の実完了数を表示。GPU単独・Legacy探索では最大5試行の完了数、Hybridの同時GPU/CPU探索ではそれぞれ最大5試行の完了数をスレッド間共有カウンターで集約し、CPU0ではGPU探索の完了後に最大3試行のCPU校正へ切り替える。**未完了試行を進捗扱いしない**。試行回数の上限で率を示し、早期終了時はバーを終了（架空の成功数を表示しない）。失敗・キャンセル・次の工程移行時も現在のタスクバーを閉じる。変換本体のページ進捗は引き続き実完了枚数で表示。
AVIFというコンテナとAV1というコーデックは共通でも、画質・色・容量の同等性は
保証しない。CPU混在比率は実行時に変動するため、推定は保証ではない。
実容量で既存の3回再調整を適用し、CPU側も自身の品質尺度を5ずつ下げる。
画質低下は品質値と再試行として記録する。70MiB超過は実験モードでは保存しない。
品質探索中は各候補についてエンコーダー終了・AVIFヘッダー／出力ファイルの基本確認と容量測定のみ行い、繰り返しの全デコード検証は行わない（実験GPU/Hybridのみ）。
破損画像を探索段階で発見できない場合があるため、最終検証で失敗した巻は保存せず、入力は変更しない。
最終CBZ保存前のデコード検証は実験GPU/Hybridに限り、先頭・末尾のAVIFと約10枚ごと（0,10,20…番目）のAVIFを抽出する約10%サンプリング方式に変更する。
本変換で使われたGPU/CPUのいずれかが抽出から漏れたら、該当エンコーダーの最初のAVIFを1枚追加する。元からあるAVIFや探索キャッシュも抽出候補に含む。
抽出した画像はFFmpegで実際にデコードし、`tools/avifdec.exe`が存在する場合は同じ抽出画像のみ独立してデコードする。
全ページについては既存のエンコーダー終了・生成AVIFヘッダー／出力サイズの基本確認を保持するが、未抽出ページの破損は見逃し得る。サンプル異常時は巻を失敗とし、CBZを保存しない。原本・既存の出力は変更しない。
最終CBZの件数・名前・順序・長さと実容量を検査後にのみ原子的に確定する。
60MiB以下は既存の無変換経路を維持する。

## 計測・受け入れ

巻ごとのJSONに総時間、各工程、各パスのGPU/CPUページ数・試行時間・平均・
スループット・空き枠秒（枠数×経過秒－稼働秒）、ピーク並列数、エラー・再試行を記録。
待機はデバイスのアイドル時間ではなくスケジューラの空き枠時間。
探索と本変換の統計はPhaseで分ける。CPU品質、GPU CQも記録する。
`Benchmark-Hybrid.ps1` は同一入力を独立ディレクトリへコピーして交互に複数回実行し、
入力SHA256・ツール情報・出力容量・品質値を保存し、成功した同条件の中央値を比較する。
画質の同等性は代表ページの目視やデコード後の画質評価で実機確認が必要。
合成モックの所要時間をNVENC性能の証拠にしない。

受け入れテスト: 250ページ、GPU12/CPU4上限・同時稼働・順序・欠損重複、
GPU失敗→CPU、CPU再試行/失敗、タイムアウト、キャンセル・後片付け、
実験モードの容量超過拒否は製品の受け入れ条件として維持する。PowerShell 7.6移行で模擬EXE依存の実プロセステストは削除し、Windows qualityではサンプル抽出・構文・検証接続を検査する。削除範囲と未検証事項は [移行仕様](./POWERSHELL_7_6.md) を参照。
