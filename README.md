# Convert-Manga — EPUB・雑誌/単巻対応・70MiB上限・最高画質優先版

Windows向けの漫画CBZ変換ツールです。漫画の巻・単巻作品・雑誌のフォルダ / ZIP / CBZ / RAR / EPUBを `Convert-Manga.bat` にまとめてドラッグ＆ドロップできます。元データは削除せず、入力元と同じ場所の **`avif変換cbz`** フォルダに結果を保存します。

## プロジェクトについて

- **実装はWindows PowerShell 5.1とBAT**。Tauri/Rustへの移行は行いません。
- CUIには全巻の進捗、現在工程、AVIFエンコード枚数と終了集計を表示します。**変換後に同じCUIへ別作品を再投入する機能はPhase 3予定**で、現在は従来通り終了時に閉じます。
- GitHubには第三者の `avifenc.exe` バイナリを含めていません。必要な場合は従来の自動取得、または `tools\avifenc.exe` への配置を利用してください。
- 開発計画は [DOCS/DEVELOPMENT_PLAN.md](DOCS/DEVELOPMENT_PLAN.md) を参照してください。

## 追加：巻数のない雑誌・単巻（One-shot）への対応

- 巻数なしの **EPUB / ZIP / CBZ / RAR** を `Convert-Manga.bat` へドラッグ＆ドロップするだけで読み込めます。
- **元ファイル名をそのまま作品名**として採用し、`v01` などの巻数は付けません。入力された複数の雑誌・単巻を、同じ作品名にまとめることはありません。
- 例：`Weekly_Ascii_2026-10-20.epub` → `avif変換cbz/Weekly_Ascii_2026-10-20.cbz`
- 例：`なんとかかんとかBest Selection.epub` → `avif変換cbz/なんとかかんとかBest Selection.cbz`
- 例：`葬送のフリーレン（１） - 山田鐘人 & アベツカサ.epub` → **従来どおり** `avif変換cbz/葬送のフリーレン v01.cbz`
- **巻数ありのシリーズ**を含む場合だけ、シリーズの作品名を一度聞きます。巻数なしの雑誌/単巻の名前には適用しません。雑誌/単巻だけなら作品名の入力はありません。AVIF並列数の入力は引き続きあります。
- **画像フォルダ**の場合、直下に `.jpg` / `.png` などの画像があり、サブフォルダやEPUB/CBZ等の巻ファイルがない巻数なしのフォルダも単巻として扱います。それ以外のフォルダはライブラリ/作品フォルダとみなし、その中を従来どおり検索します。
- 出力先・スキップ規則、EPUBの本文画像の順序、60MiB以下の無変換ルール、60MiB超のAVIF自動品質調整は変更しません。
- `（１）` などの巻数がタイトル中にある場合は巻物と判定する従来の規則を優先します。日付（例：`2026-10-20`）は巻数にはしません。
- `Weekly_Ascii_2026-10-20` のような日付を持つ**ファイル名**は対応します。EPUB内部がDRM付き、文字主体などで画像を抽出できない場合は従来どおりエラーになります。

## 今回追加：漫画EPUBを読書順に変換

- **EPUBをBATへ直接ドラッグ＆ドロップ**できます（ZIP / CBZ / RAR / 巻フォルダと混在可）。EPUB単独の場合、WinRARは不要です。
- EPUB 2/3の `META-INF/container.xml` → `content.opf` 内の **spine（公式の読書順）** → XHTML / SVGの画像参照を解析。元画像名がバラバラでも、ページ順を維持します。
- 画像を `001.jpg`、`002.png` ... として連番化します。1000ページを超える場合などはページ数に合わせて桁数が増えます。拡張子は元画像に合わせます。
- OPFの表紙指定 (`cover-image`、EPUB 2の `meta name="cover"`) があって、その画像が本文に含まれていない場合、表紙を先頭に一度だけ追加します。
- 画像の抽出・番号付け後は、**これまでの60MiB判定・AVIF変換・70MiB容量調整・CBZ保存処理をそのまま共用**します。
- 既存の保存ルール、シリーズ作品名を1回だけ入力する方式、元ファイル保持、出力先 `avif変換cbz` は変更しません。

### EPUB対応範囲・注意

- **漫画など画像主体のEPUBが対象**です。JPEG/JPG、PNG、WebP、GIF、BMP、AVIFページに対応します（従来通りAVIFへの再圧縮対象はJPEG / PNG / WebPのみ）。
- XHTMLの `<img>`、SVGの `<image>`、`<object data="...">` で参照された画像を、spineで指定された順番に抽出します。スキャン元の画像ファイル名で勝手に並べ替えません。
- **文字主体の小説、CSS背景画像だけのページ、SVGのベクター図形だけのページ、DRM等の暗号化画像には非対応**。対応できないページがあれば警告付きの不完全なCBZを作らず、その巻の変換を失敗させます。
- ZIP内の本文画像だけを専用の一時フォルダへ抽出し、元EPUBは変更しません。外部URL参照やEPUB外へのパス移動は拒否します。
- **60MiB以下のEPUBは画像を連番に並べ替えてCBZ化しますが、AVIF再圧縮はしません**（既存ルール）。60MiBを超えるEPUBはJPEG/PNG/WebPをAVIFへ変換します。品質「70固定」ではなく、既存と同じく**完成容量70MiB以下を目指して品質30～95を自動選択**します。
- シリーズ扱いするEPUBには巻数表記を付けてください（例：`ONE PIECE v50.epub`、`50巻.epub`、`（１５）.epub`）。巻数のないEPUBは自動的に単巻・雑誌として変換します。

## EPUBファイル名末尾の著者情報にも対応

- `葬送のフリーレン（１） - 山田鐘人 & アベツカサ.epub` → 認識する作品名 `葬送のフリーレン`、巻数 `1`、出力 `葬送のフリーレン v01.cbz`。
- `作品名（１５） - 著者名.epub`、`作品名 (15) - 作者 & 作画.epub` といった、巻数の後に ` - ` と著者クレジットが続く名前を受け付けます。
- `（１５） - 著者名.epub` は、シリーズフォルダ内にあれば親フォルダ名から作品名を補います。
- 著者名は出力CBZの作品名に含めません。変更するのは**入力ファイル名の判定**のみで、EPUB内部の画像抽出順やAVIFの容量調整は従来どおりです。
- ファイルが巻数判定を通過しても、EPUB自体のDRM・画像形式・内部構造などの理由で変換に失敗する場合があります。エラー表示を確認してください。

## 巻数名の追加対応（全角括弧・全角数字）

- `（１５）.epub`、`(15).cbz`、`（１５）` フォルダを巻数15として扱います。
- `作品名（１５）.epub`、`作品名 (15).zip`、`作品名（第１５巻）.rar` にも対応します。
- `１５巻`、`v１５`、`作品名+１５巻` のような全角数字も半角の巻数に揃えて出力します。
- 例：`（１５）.epub`（作品フォルダ内）→ 作品名を最初に一度入力 → `作品名 v15.cbz`。
- 括弧付き数字だけのファイルは作品名を持たないため、従来通り親フォルダ名を候補に使用し、入力画面で変更できます。
- 原本のファイル名・作品タイトルの文字は変更せず、巻数を出力名に使うときだけ正規化します。

## 変更内容

- **60MiB以下**の元CBZはAVIF変換せず **そのままコピー**（画像の内容・画質を変更しません）。ZIP / RAR / EPUB / フォルダ入力では、無変換でCBZへ詰め直します（EPUBはページを連番化）。
- **60MiB超**の巻は、**70MiB以内で最高品質**を目指してAVIF品質を自動選択します。従来の「60MiBに近い品質を選ぶ」処理は廃止しました。
- 入力名 `作品名 v100b.cbz`、`v100b.cbz`（シリーズフォルダ内）、`作品名 v03a.cbz`、`作品名+100b巻.zip`、`v100b` フォルダ（シリーズフォルダ内）など、**英字の枝番**を認識します。**出力時には末尾の `b` / `B` だけを取り除きます**（例：`v100b` → `v100`）。`a` などほかの枝番は維持します。
- 画像単位の **AVIF並列変換**に対応（デフォルトは論理CPU数の半分、最大8並列、手動1〜16）。
- 既存のWebPをAVIFにする場合は、一度 `dwebp.exe` でPNGへ可逆展開します。**WebPでの出力機能はありません。**

## 使い方

1. ZIPを展開し、`Convert-Manga.bat`・`Convert-Manga.ps1`・`Convert-Manga-Epub.ps1`・`Convert-Manga-Progress.ps1` を同じフォルダに置きます（ZIPを展開したまま使用）。
2. 漫画のEPUB・CBZ・ZIP・RARや巻フォルダなどをBATへドラッグ＆ドロップします（複数指定可）。
3. **巻数ありのシリーズが含まれるときだけ**作品名を1回入力。Enterなら検出した作品名を採用し、シリーズ巻に適用します。単巻・雑誌は元の名前をそのまま使います。
4. **並列数**を入力。Enterなら自動設定です。
5. 自動的に元の容量を判定し、必要な場合だけAVIFへ変換します。

```text
ONE PIECE/
├── ONE PIECE v100b.cbz         ← 元ファイル（保持）
├── ONE PIECE v101.cbz          ← 元ファイル（保持）
└── avif変換cbz/
    ├── ONE PIECE v100.cbz      ← v100b から変換／コピー
    └── ONE PIECE v101.cbz      ← 通常巻はそのままの番号
```

**同名の出力CBZが既に存在する場合は、上書きせずスキップ**します。また、`v100.cbz` と `v100b.cbz` を同時に入力すると、両方の出力名は `v100.cbz` になります。この場合は通常巻 `v100.cbz` を優先し、`v100b.cbz` 側は警告を表示してスキップします。旧版の出力を再作成する場合は `avif変換cbz` 内の対象巻だけを移動または削除してください。

## 自動画質選択の流れ（高速化版）

1. 元CBZが **60MiB（62,914,560バイト）以下**なら元データを無変換コピー。
2. 60MiB超の巻では、変換対象のJPEG/PNG/WebPから **最大12ページ**を均等に選んで試算します（以前は最大20ページ）。
3. AVIF品質 **30〜95** の候補を **最大5回**の二分探索で調べます（以前は最大7回）。内部の目標値は **68MiB**。70MiBの上限に2MiBの余裕を持たせています（ZIP管理情報の概算も考慮）。
4. **68MiB以下と推定できる中で最も高い、テスト済み品質**を選びます。候補が見つからなければ、試算した中で最も低い品質から始めます。
5. **採用した品質で試算済みの最大12ページを再利用**し、残りのページだけ並列エンコードします。このため試算ページを同品質で変換し直す必要がありません。
6. 全画像の容量（ZIP管理情報の概算込み）が **70MiB以内**なら終了。**70MiB超過時だけ**、既存の試算結果と実際の容量差を使って品質を下げ、再試行します。再試行では **追加のサンプル探索はしません**。全ページ変換は最大合計3回です。
7. 完成CBZの画像数・名前・サイズを検証し、出力先へ保存します。どうしても70MiB以下にならない場合は、最も小さかった試行結果を警告付きで保存します。

### 処理の効率について

- 代表ページのテスト回数は **最大60画像分（12枚×5品質）**。以前は最大140画像分（20枚×7品質）でした。
- 採用品質で試算した画像は、本番変換でもそのまま流用します。
- 最大5回という制限のため、**厳密な最高品質**を必ず突き止めるわけではありません。速度と画質のバランスを優先し、テストした品質の中で最良の候補を選びます。
- 68MiBは予測目標であり、70MiB以内への収まりを保証するものではありません。

### 変換設定

- `avifenc.exe -q <自動選択品質> -s 6 -j 1`（**`-s 6` は変更なし**。AVIFエンコーダー内部は1スレッド、複数ページを並列変換）。
- ページ順と元の解像度を維持し、ZIP無圧縮（Store）形式のCBZを作成。
- 元のCBZ、ZIP、RAR、画像は**削除・上書きしません**。変換失敗時は一時ファイルを破棄します。

## 必要なもの

- Windows PowerShell 5.1（Windows標準）
- WinRAR（ZIP / CBZ / RARを開くため。EPUB単独やフォルダ入力だけなら不要）
- AOMedia公式 `avifenc.exe`：最初のAVIF変換時に公式リリースから自動取得。自動取得できない場合は `tools\avifenc.exe` に配置。
- Google公式 `dwebp.exe`：元CBZにWebP画像がある場合だけ必要。自動取得が失敗した場合は `tools\dwebp.exe` に配置。

公式サイト: https://github.com/AOMediaCodec/libavif/releases および https://developers.google.com/speed/webp/download

## 注意

- JPEGやWebP→AVIFは**非可逆の再エンコード**です。画質が改善するわけではありません。Kavita・Mihonでの表紙とページ表示、細い文字・トーンを最初の1巻で確認してください。
- 数値表記は「MiB」（1MiB = 1,048,576バイト）です。Windowsのファイル容量表示に近い単位です。
- **Windows実機での実変換は未検証**です。配布ZIPの内容とスクリプトを検査しています。初めに少数ページのEPUB・1巻で確認してください。
