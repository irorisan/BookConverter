# BookConverter — 漫画と雑誌の専用BAT・AVIF/CBZ変換

Windows向けの漫画・雑誌CBZ変換ツールです。**漫画は `Convert-Manga.bat`、雑誌・単巻は `Convert-Manga-Magazine.bat`** にフォルダ / ZIP / CBZ / RAR / EPUBをドラッグ＆ドロップします。元データは削除せず、入力元の親に **`avif変換cbz`** を作成して結果を保存します。

## プロジェクトについて

- **実装はPowerShell 7.6（Windows / .NET 10）とBAT**。Tauri/Rustへの移行は行いません。
- CUIには全巻の進捗、現在工程、AVIFエンコード枚数と終了集計、**変換所要時間（HH:MM:SS.1桁）**を表示します。さらに、各巻の終了時に入力準備・展開・品質探索・本変換・AVIF検証・CBZ作成/検証などの**工程別所要時間**を表示します。時間はシリーズ名・CPU版の並列数入力後から完了集計まで（解凍・品質探索・CBZ保存・検証を含む）を測定します。変換後は同じCUIで次の作品のパス入力を待ち、`q` / `exit` で終了します。
- GitHubには第三者の `avifenc.exe` バイナリを含めていません。必要な場合は従来の自動取得、または `tools\avifenc.exe` への配置を利用してください。
- 開発計画は [DOCS/DEVELOPMENT_PLAN.md](DOCS/DEVELOPMENT_PLAN.md) を参照してください。

## NVIDIA GPU（NVENC）でのAVIF変換

**正式なGPUモードを追加しました。** RTX 40/50などのAV1 NVENC対応GPUが必要です。
既存のCPUモードはそのまま利用でき、画像と出力CBZの保存ルールも共通です。

| 起動BAT | 変換エンジン | モード |
|---|---|---|
| `Convert-Manga-GPU.bat` | `ffmpeg.exe / av1_nvenc` | 漫画・GPU |
| `Convert-Manga-Magazine-GPU.bat` | `ffmpeg.exe / av1_nvenc` | 雑誌・GPU |
| `Convert-Manga.bat` | `avifenc.exe / CPU` | 漫画・CPU |
| `Convert-Manga-Magazine.bat` | `avifenc.exe / CPU` | 雑誌・CPU |

- `ffmpeg.exe` は**同梱しません**。NVENCエンコーダー・AVIF muxer付きのWindowsビルドを用意し、`tools\ffmpeg.exe` に置くかPATHへ追加します。
- GPU版は**FFmpeg 12プロセス × 各1画像**の固定構成です。品質探索とAVIF本変換の両方で、各プロセスが1画像ずつ独立したAVIFを作成します。GPU版では並列数の入力は不要です（CPU版は従来の1〜16並列を選択可能）。AVIFデコード検証は全ページを対象に**8画像ずつ・最大2プロセス**で実施します。**`-preset p7` 固定**、`-pix_fmt yuv420p`を維持します。250ページでの単回ベンチマークでは12×1が41.7秒、6×2が43.0秒、4×3が44.5秒、3×4が46.3秒でした。
- 元ファイルが60MiB以下なら再圧縮しません。60MiB超では従来の最大12ページ×最大5回の試算で容量を調整し、70MiB以内を目指します。70MiB超過時は従来どおり警告付きで保存する場合があります。
- Legacy GPUで生成されたAVIFはヘッダーと**全ページのFFmpegデコード**で検証します。実験GPU/Hybridは [Hybrid仕様](DOCS/HYBRID_AVIF.md) の最終サンプル検証を使用します。検証は**8ページずつまとめてFFmpegを起動**する方式で、FFmpegの起動回数を削減します。250ページなら約32起動です（効果は環境で変動）。検証エラーは成功扱いにせず中断します。`tools\avifdec.exe` があればlibavifでの追加検証も全ページ実施します。
- NVENC実行エラー時は**黙ってCPU版へ切り替えません**。元データを保持したまま当該巻を失敗扱いとします。CPUを使う場合は従来のBATで実行してください。
- CPUの画質設定QとGPUのCQは同一画質を示すものではありません。GPUモードの品質探索は独立した尺度として扱います。
- 出力先は両方式とも `avif変換cbz`。既存の同名作品があれば安全のためスキップするので、比較時は生成済みのCBZを別の場所に移してから再変換してください。
- KavitaやMihonでの表紙・本文表示は最初の数巻で確認することを推奨します。Windows/NVIDIA GPU実機テストはCIでは実行していません。

**自分用の更新機能**：`Update-BookConverter.bat` を実行すると、GitHub `irorisan/BookConverter` の**最新main**をZIPで取得して更新します。Gitコマンドは不要です。

- ローカルの `tools/` と `.git/`、漫画入力・出力フォルダ、GitHub管理対象外のファイルは削除・更新しません。
- アップデーターは最新mainにあるファイルだけを更新し、古いファイルや個人用ファイルを自動削除しません。
- 更新対象のファイルは一時的にバックアップし、途中で失敗すると書き換えたものを元に戻します。
- 変換中は実行せず、変換終了後に更新してください。GitHubへの接続が必要です。
- GitHub本体に組み込まれるバックグラウンド更新機能ではありません。BATから手動実行する個人用ユーティリティです。

## 漫画と雑誌のBATを使い分ける

| 起動ファイル | 入れるもの | 作品名の扱い |
|---|---|---|
| `Convert-Manga.bat` | 普通の漫画・巻物・漫画EPUB・巻フォルダ | **巻数が読めなくても**シリーズ名を1バッチ1回入力できる。巻数認識ありは `作品名 v01.cbz`、番号不明は `指定作品名 - 入力ベース名.cbz`（両者同名なら `指定作品名.cbz`） |
| `Convert-Manga-Magazine.bat` | 雑誌・単巻・特集号 | シリーズ名は尋ねず、**すべて元ベース名のまま** `.cbz` へ出力。ファイル名に `(15)` などがあっても巻数認識で変更しない |

漫画でも巻数の認識に失敗する名前があります。**巻数の有無では漫画/雑誌を判定しません。** 作品名を揃えたい場合は漫画BATを使ってください。漫画BATでは `Manga-Zip.info_10.cbz` のような**末尾 `_数字` を10巻と認識**し、指定作品名が「ドロヘドロ」なら `ドロヘドロ v10.cbz` に統一します。`ドロヘドロ v18.cbz` も従来どおり認識します。識別できない名前だけ元名を残し、架空の巻番号は付けません。**雑誌BATは `_数字` があっても元名を維持**します。

例（漫画BATで作品名「星の話」を指定）:

```text
星の話（１）.cbz       → 星の話 v01.cbz
星の話 外伝.cbz       → 星の話 - 星の話 外伝.cbz
星の話 特装版.cbz     → 星の話 - 星の話 特装版.cbz
```

例（雑誌BAT）:

```text
Weekly_Ascii_2026-10-20.epub → Weekly_Ascii_2026-10-20.cbz
月刊誌 (15).cbz             → 月刊誌 (15).cbz
```

両BATとも同じPowerShell変換エンジンを使い、進捗、出力先、元データ保護、AVIF/EPUB処理、変換後の次入力待機は共通です。**一度起動したCUI内ではモードが固定**されるため、漫画と雑誌を切り替えるときは対応するBATを開き直します。詳しくは[入口分離仕様](DOCS/MODE_SEPARATION.md)。

## 漫画EPUBを読書順に変換

- **EPUBをBATへ直接ドラッグ＆ドロップ**できます（ZIP / CBZ / RAR / 巻フォルダと混在可）。EPUB単独の場合、WinRARは不要です。
- EPUB 2/3の `META-INF/container.xml` → `content.opf` 内の **spine（公式の読書順）** → XHTML / SVGの画像参照を解析。元画像名がバラバラでも、ページ順を維持します。
- 画像を `001.jpg`、`002.png` ... として連番化します。1000ページを超える場合などはページ数に合わせて桁数が増えます。拡張子は元画像に合わせます。
- OPFの表紙指定 (`cover-image`、EPUB 2の `meta name="cover"`) があって、その画像が本文に含まれていない場合、表紙を先頭に一度だけ追加します。
- 画像の抽出・番号付け後は、**これまでの60MiB判定・AVIF変換・70MiB容量調整・CBZ保存処理をそのまま共用**します。
- 既存の保存ルール、シリーズ作品名を1回だけ入力する方式、元ファイル保持、出力先 `avif変換cbz` は変更しません。

### EPUB対応範囲・注意

- **漫画など画像主体のEPUBが対象**です。JPEG/JPG、PNG、WebP、GIF、BMP、AVIFページに対応します（従来通りAVIFへの再圧縮対象はJPEG / PNG / WebPのみ）。
- XHTMLの `<img>`、SVGの `<image>`、`<object data="...">` で参照された画像を、spineで指定された順番に抽出します。スキャン元の画像ファイル名で勝手に並べ替えません。
- **文字主体の小説、CSS背景画像だけのページ、SVGのベクター図形だけのページ、DRM等の暗号化画像には非対応**。対応できないページがあれば警告付きの不完全なCBZを作らず、その巻の変換を失敗させます。
- ZIP内の本文画像だけを専用の一時フォルダへ抽出し、元EPUBは変更しません。外部URL参照やEPUB外へのパス移動は拒否します。
- **60MiB以下のEPUBは画像を連番に並べ替えてCBZ化しますが、AVIF再圧縮はしません**（既存ルール）。60MiBを超えるEPUBはJPEG/PNG/WebPをAVIFへ変換します。品質「70固定」ではなく、既存と同じく**完成容量70MiB以下を目指して品質30～95を自動選択**します。
- 巻数表記があるEPUB（例：`ONE PIECE v50.epub`、`50巻.epub`、`（１５）.epub`）は漫画BATで巻数を認識します。巻数のないEPUBでも、漫画BATならシリーズ名を入力して元名を識別子として保持します。雑誌BATなら元のEPUBベース名を保持します。

## EPUBファイル名末尾の著者情報にも対応

- `葬送のフリーレン（１） - 山田鐘人 & アベツカサ.epub` → 認識する作品名 `葬送のフリーレン`、巻数 `1`、出力 `葬送のフリーレン v01.cbz`。
- `作品名（１５） - 著者名.epub`、`作品名 (15) - 作者 & 作画.epub` といった、巻数の後に ` - ` と著者クレジットが続く名前を受け付けます。
- `（１５） - 著者名.epub` は、シリーズフォルダ内にあれば親フォルダ名から作品名を補います。
- 著者名は出力CBZの作品名に含めません。変更するのは**入力ファイル名の判定**のみで、EPUB内部の画像抽出順やAVIFの容量調整は従来どおりです。
- ファイルが巻数判定を通過しても、EPUB自体のDRM・画像形式・内部構造などの理由で変換に失敗する場合があります。エラー表示を確認してください。

## 巻数名の追加対応（全角括弧・全角数字）

- `（１５）.epub`、`(15).cbz`、`（１５）` フォルダを巻数15として扱います。
- `作品名（１５）.epub`、`作品名 (15).zip`、`作品名（第１５巻）.rar` にも対応します。
- `１５巻`、`v１５`、`作品名+１５巻` のような全角数字も半角の巻数に揃えて出力します。
- 例：`（１５）.epub`（作品フォルダ内）→ 作品名を最初に一度入力 → `作品名 v15.cbz`。
- 括弧付き数字だけのファイルは作品名を持たないため、従来通り親フォルダ名を候補に使用し、入力画面で変更できます。
- 原本のファイル名・作品タイトルの文字は変更せず、巻数を出力名に使うときだけ正規化します。

## 変更内容

- **60MiB以下**の元CBZはAVIF変換せず **そのままコピー**（画像の内容・画質を変更しません）。ZIP / RAR / EPUB / フォルダ入力では、無変換でCBZへ詰め直します（EPUBはページを連番化）。
- **60MiB超**の巻は、**70MiB以内で最高品質**を目指してAVIF品質を自動選択します。従来の「60MiBに近い品質を選ぶ」処理は廃止しました。
- 入力名 `作品名 v100b.cbz`、`v100b.cbz`（シリーズフォルダ内）、`作品名 v03a.cbz`、`作品名+100b巻.zip`、`v100b` フォルダ（シリーズフォルダ内）など、**英字の枝番**を認識します。**出力時には末尾の `b` / `B` だけを取り除きます**（例：`v100b` → `v100`）。`a` などほかの枝番は維持します。
- 画像単位の **AVIF並列変換**に対応（デフォルトは論理CPU数の半分、最大8並列、手動1〜16）。
- 既存のWebPをAVIFにする場合は、一度 `dwebp.exe` でPNGへ可逆展開します。**WebPでの出力機能はありません。**

## 使い方

1. ZIPを展開して `BookConverter/` のBATを起動します。PowerShellファイルは `scripts/` にまとめて配置します。`tools/` に外部エンコーダーを置きます。
2. 漫画は `Convert-Manga.bat`、雑誌は `Convert-Manga-Magazine.bat` を選び、EPUB・CBZ・ZIP・RARや巻フォルダをドラッグ＆ドロップします（複数可）。引数なし起動の場合は待機プロンプトに絶対パスを貼り付けてEnter。空白を含む複数パスはそれぞれダブルクォートで囲みます。
3. **漫画BATでは巻数の有無にかかわらず作品名を1回入力**。Enterなら最初の検出名を採用。**雑誌BATでは名前入力なし**で元名を保持します。
4. **並列数**を入力。Enterなら自動設定です。
5. 自動的に元の容量を判定し、必要な場合だけAVIFへ変換します。
6. 結果集計後、同じモードで次の作品のパスを入力してEnter。漫画の作品名と並列数はバッチごとに指定します。空行・無効パスは再入力できます。終了は待機中に `q` / `exit`。

コンソールへのドロップは対応ホストでパスを挿入してEnterで確定します。Windows Terminal / Console Hostの実際のドロップ動作は未確認です。対応しない場合も「パスのコピー」→貼り付けを利用できます。多数ファイルは親フォルダを指定してください。

```text
ONE PIECE/
├── ONE PIECE v100b.cbz         ← 元ファイル（保持）
├── ONE PIECE v101.cbz          ← 元ファイル（保持）
└── avif変換cbz/
    ├── ONE PIECE v100.cbz      ← v100b から変換／コピー
    └── ONE PIECE v101.cbz      ← 通常巻はそのままの番号
```

**同名の出力CBZが既に存在する場合は、上書きせずスキップ**します。また、`v100.cbz` と `v100b.cbz` を同時に入力すると、両方の出力名は `v100.cbz` になります。この場合は通常巻 `v100.cbz` を優先し、`v100b.cbz` 側は警告を表示してスキップします。旧版の出力を再作成する場合は `avif変換cbz` 内の対象巻だけを移動または削除してください。

## 自動画質選択の流れ（高速化版）

1. 元CBZが **60MiB（62,914,560バイト）以下**なら元データを無変換コピー。
2. 60MiB超の巻では、変換対象のJPEG/PNG/WebPから **最大12ページ**を均等に選んで試算します（以前は最大20ページ）。
3. AVIF品質 **30〜95** の候補を **最大5回**の二分探索で調べます（以前は最大7回）。内部の目標値は **68MiB**。70MiBの上限に2MiBの余裕を持たせています（ZIP管理情報の概算も考慮）。
4. **68MiB以下と推定できる中で最も高い、テスト済み品質**を選びます。候補が見つからなければ、試算した中で最も低い品質から始めます。
5. **採用した品質で試算済みの最大12ページを再利用**し、残りのページだけ並列エンコードします。このため試算ページを同品質で変換し直す必要がありません。
6. 全画像の容量（ZIP管理情報の概算込み）が **70MiB以内**なら終了。**70MiB超過時だけ**、既存の試算結果と実際の容量差を使って品質を下げ、再試行します。再試行では **追加のサンプル探索はしません**。全ページ変換は最大合計3回です。
7. 完成CBZの画像数・名前・サイズを検証し、出力先へ保存します。どうしても70MiB以下にならない場合は、最も小さかった試行結果を警告付きで保存します。

### 処理の効率について

- 代表ページのテスト回数は **最大60画像分（12枚×5品質）**。以前は最大140画像分（20枚×7品質）でした。
- 採用品質で試算した画像は、本番変換でもそのまま流用します。
- 最大5回という制限のため、**厳密な最高品質**を必ず突き止めるわけではありません。速度と画質のバランスを優先し、テストした品質の中で最良の候補を選びます。
- 68MiBは予測目標であり、70MiB以内への収まりを保証するものではありません。

### 変換設定

- `avifenc.exe -q <自動選択品質> -s 6 -j 1`（**`-s 6` は変更なし**。AVIFエンコーダー内部は1スレッド、複数ページを並列変換）。
- ページ順と元の解像度を維持し、ZIP無圧縮（Store）形式のCBZを作成。
- 元のCBZ、ZIP、RAR、画像は**削除・上書きしません**。変換失敗時は一時ファイルを破棄します。

## 必要なもの

- PowerShell 7.6.x（Windows版、`pwsh.exe` をPATHへ登録）。Windows標準の5.1は対象外。インストール・移行・検証範囲は [PowerShell 7.6移行仕様](DOCS/POWERSHELL_7_6.md) を参照。
- WinRAR（ZIP / CBZ / RARを展開する場合。60MiB以下のCBZ原本コピー・EPUB・フォルダ入力では不要）
- AOMedia公式 `avifenc.exe`：最初のAVIF変換時に公式リリースから自動取得。自動取得できない場合は `tools\avifenc.exe` に配置。
- Google公式 `dwebp.exe`：元CBZにWebP画像がある場合だけ必要。自動取得が失敗した場合は `tools\dwebp.exe` に配置。

公式サイト: https://github.com/AOMediaCodec/libavif/releases および https://developers.google.com/speed/webp/download

## 注意

- JPEGやWebP→AVIFは**非可逆の再エンコード**です。画質が改善するわけではありません。Kavita・Mihonでの表紙とページ表示、細い文字・トーンを最初の1巻で確認してください。
- 数値表記は「MiB」（1MiB = 1,048,576バイト）です。Windowsのファイル容量表示に近い単位です。
- **WinRAR・avifenc・dwebpを使うWindows実機E2Eは未検証**です。CIではPowerShell 7.6のBAT連続変換・小型CBZのSHA-256・EPUB/spine・自然順・命名・容量境界を検証します。実機ドロップも未確認です。[実機の確認手順](DOCS/PHASE3_4_CONTINUOUS.md) に従い、初めに少数ページ・1巻で確認してください。
GPU12＋CPU4の実験は [設計・測定手順](DOCS/HYBRID_AVIF.md) を参照。
`Convert-Manga-Hybrid.bat`（漫画）または `scripts/Convert-Manga.ps1 -ConversionMode Hybrid`
で明示起動する。比較用は `-ConversionMode GPU`。Hybridの対話起動ではCPU品質探索の並列数を**0〜8（Enterで4）**から選べる。引数 `-CpuProbeWorkers 8` でも指定可能。**0はCPU品質探索のみ省略**し、CPU本変換の既定4並列は維持する。自動実行・パイプ入力では既定4を使う。詳しくは[設計・測定手順](DOCS/HYBRID_AVIF.md)。既存BATの既定動作は変わらない。
